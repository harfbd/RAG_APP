01 / FIELDWORK

從農業現場，看見資訊落差

農友遇到葉片異常或管理疑問時，需要把作物、症狀、生育階段和環境一起判斷；有用的資訊卻分散在不同手冊與資料來源。

現地觀察

把真實問題帶回設計桌

團隊走進農業場域，觀察種植設施與管理工作，並把訪談重點轉化為手機問答、照片上傳和紀錄回查等系統需求。

照片來源：專題作品說明書
02 / USER NEEDS

把觀察轉成可操作的需求

研究沒有從功能清單開始，而是先釐清農友在田間提問時需要什麼：少打字、看得懂、能追查，還能回頭找曾經問過的事。

01問題要容易輸入

以自然語言描述作物、症狀與情境，手機上就能提問。

02建議要有依據

回答附上手冊作物與頁碼，必要時區分網路補充資訊。

03操作要能回顧

留下文字查詢與照片紀錄，方便比較不同時間的狀況。

研究目標

讓栽培手冊從「需要翻找的文件」，變成手機上可提問、可回查的資訊入口。

03 / KNOWLEDGE BASE

先整理資料，再讓模型回答

知識來源以農業機關公開的栽培手冊為主。團隊把文件清理、切分為段落，保留作物、文件與頁碼，建立問答時可檢索的索引。

以中文栽培手冊建立主要知識庫；圖為其中兩份資料。

04 / HOW RAG WORKS

RAG：先找資料，再組織回答

檢索增強生成把「找相關內容」放在「產生文字」之前。以農友的一個問題為例，依序點選下方五個步驟，看資料如何進入回答。

示意提問「小黃瓜葉片發黃，應該先檢查什麼？」實際回答仍需提供生育階段、環境與葉片症狀等資訊。

05 / SYSTEM DESIGN

從手機畫面到手冊來源

系統採用可在手機瀏覽器使用的 PWA 原型。前端承接提問與顯示結果，後端負責檢索、生成及來源整理；外部模型服務的金鑰保留在後端。

06 / MOBILE WALKTHROUGH

沿著手機畫面，走一次使用流程

點選四個操作節點，查看專題原型的實際截圖。文字問答、來源列示與紀錄回查已有實作；拍照病名辨識的畫面則屬模擬展示。

實際原型截圖首頁提供明確的操作入口

農友可以從首頁選擇症狀提問、檢視紀錄，或查看當地天氣資訊。

關於拍照診斷

照片上傳與結果頁面可展示操作流程；目前病名辨識及畫面中的信心度是模擬資料，不代表模型準確率。

07 / EVALUATION

把已完成的成果與限制講清楚

初步測試包括手冊內容比對、手機操作及農友回饋。現階段資料仍不足以提出正式的問答正確率或使用效益統計。

目前已實作
  • 手冊與網路補充資料的文字問答
  • 回答來源標示與頁碼回查
  • 手機介面、照片上傳與查詢紀錄
  • 依操作回饋調整提示與流程
尚需驗證或介接
  • 正式問答測試集與專家評分
  • 真實影像病名辨識及準確率
  • 農場感測器資料與環境趨勢
  • 更完整的農友使用樣本
「來源可查」是起點，
「建議可靠」還需要驗證。

引用手冊能幫助回查，卻不能代替作物情境判讀。遇到資料不足、症狀不明或涉及用藥的問題，仍應諮詢農業專家。
